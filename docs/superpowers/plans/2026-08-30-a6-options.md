## 1. Primary sources

Binance options have a single first-party archive surface at
`https://data.binance.vision/data/option/daily/`, with two
sub-archives:

- `BVOLIndex/BTCBVOLUSDT/BTCBVOLUSDT-BVOLIndex-YYYY-MM-DD.zip` — the
  Binance Volatility Index (annualized IV proxy, 1-second
  resolution).
- `EOHSummary/BTCUSDT/BTCUSDT-EOHSummary-YYYY-MM-DD.zip` — end-of-hour
  summary of every live option contract (price, volume, greeks,
  OI).

There is **no options archive under `data/futures/um/`** and no
`data/options/` (plural) directory. The `data/option/` (singular)
directory is the only options surface on `data.binance.vision`.

## 4. Format and field semantics

### 4.1 BVOL index

5-column CSV at 1-second resolution:

| Column | Field | Meaning |
| --- | --- | --- |
| 0 | `calc_time` | bar open in UTC ms |
| 1 | `symbol` | always `BTCBVOLUSDT` (the synthetic index ticker) |
| 2 | `base_asset` | always `BTCBVOL` (legacy / chain) |
| 3 | `quote_asset` | always `USDT` |
| 4 | `index_value` | annualized IV in percent (47.3320 = 47.33 %) |

**Strictly backward-looking:** `index_value` at time `T` is the
TWA of the implied-vol surface at `T`. Causally available at `T`
and at any later bar.

**Quirks:**

- 2023-06-20 has 85,700 records (instead of 86,400) — the first
  day is short, presumably because the archive started mid-day.
- 2023-12-31 onward have 86,400 records (1/sec × 24h). The series
  is uniformly spaced at 1-second resolution.

### 4.2 EOH summary

26-column CSV at **1-hour resolution** (24 rows per day per
contract):

| Column | Field | Meaning |
| --- | --- | --- |
| 0 | `date` | trading date UTC |
| 1 | `hour` | hour 00–23 UTC |
| 2 | `symbol` | option contract symbol (e.g. `BTC-230519-33000-C`) |
| 3 | `underlying` | always `BTCUSDT` |
| 4 | `type` | `C` (call) or `P` (put) |
| 5 | `strike` | strike and expiry in YYMMDD-K format |
| 6–11 | OHLCV | open, high, low, close, volume_contracts, volume_usdt |
| 12–15 | best_bid_price, best_ask_price, best_bid_qty, best_ask_qty | top-of-book snapshots at the hour |
| 16–17 | best_buy_iv, best_sell_iv | IV at best bid / best ask (annualized %) |
| 18–19 | mark_price, mark_iv | mark price and mark IV (annualized %) |
| 20–23 | delta, gamma, vega, theta | Black-Scholes greeks |
| 24–25 | openinterest_contracts, openinterest_usdt | end-of-hour OI in contracts / USDT notional |

**This is exactly the data the audit needs** for skew, risk
reversal, and OI features. A loader can build:

- **At-the-money IV** from the contract with strike closest to
  the underlying mark.
- **25-delta risk reversal (RR)** = `IV(25d call) - IV(25d put)`.
- **25-delta butterfly (BF)** = `(IV(25d call) + IV(25d put))/2 - IV(ATM)`.
- **OI-weighted IV surface** from the `openinterest_contracts`
  column.

But: **the EOH archive is a 5-month sliver.** Building
features on 2020-2024 with EOH is impossible because 4.5 years of
the audit window are uncovered.

## 5. Publication delay and revision behavior

- BVOL and EOH daily zips are published on a T+1 schedule
  (consistent with other `data.binance.vision` archives).
- The ETag is the SHA-256 of the zip body; the adjacent
  `.CHECKSUM` file carries the same hash with a two-space-
  separated filename suffix. Every probed month's recomputed
  SHA-256 matches its `.CHECKSUM` file sidecar exactly.
- No rate limiting observed.

## 6. Licensing and retention/redistribution rights

Both archives are the **same operator** (Binance), the **same S3
bucket** (`data.binance.vision`), and the **same** "public market
data, free for non-commercial use" framing that already covers
the kline / mark / index / funding / OI / premium archives. The
existing `configs/legal/binance-usdm-provider-rights.v3.yaml`
record is the source of truth and covers this surface.

The audit notes that **options data has a separate Binance Options
Terms of Use** that the owner may want to review separately; the
existing rights record should be amended to add a dedicated
options clause rather than relying on the indirect USD-M coverage.
For the audit, the existing record is sufficient and no new
clearance is required.

**No redistribution.** Quantara never re-publishes the underlying
bytes. The pipeline stores content-addressed originals and serves
derived aggregates only inside the pipeline boundary.

## 8. Fallback for 2020-01-01 → 2023-05-17

The 3.4-year pre-2023-05-18 options gap is **not** covered by any
Binance public archive. Fallback candidates, in priority order:

1. **Deribit** historical options data — Deribit is the dominant
   BTC/ETH options venue and has archived volatility history from
   2017 onward. Deribit is not Binance but is **the** source for
   long-history BTC options IV. Paid data product; license
   review still required. **Strongly recommended** as the fallback
   for the 2020-01-01 → 2023-05-17 window.
2. **CoinGlass** (https://www.coinglass.com/pro/futures/Liquidations)
   — multi-exchange IV history; vendor fallback.
3. **CoinAPI** historical options metrics API.

**Recommendation for the post-A10 protocol freeze:** treat
options-derived features as **inactive** for 2020-01-01 →
2023-05-17, and **active** (from BVOL only) for 2023-06-20
onward, **until** a separate audit evaluates a Deribit or
CoinGlass fallback and the owner authorises its inclusion. The
post-A10 protocol should not pretend to have options data it
does not have.

## 9. Implications for the target / protocol design

The audit's A6 result interacts with the protocol design in
three ways:

1. **No historical options-derived feature for 2020-01-01 →
   2023-05-17.** A model that needs skew or RR for regime
   labelling cannot get it from first-party source.
2. **BVOL is available from 2023-06-20 onward.** It is a **single
   number per second** (an ATM IV proxy), which is enough for
   "fear-gauge" type features but not enough for skew, RR, or
   BF.
3. **EOH is a 5-month sliver only.** The audit treats EOH as
   **out of scope for production features** because a 5-month
   sample cannot support robust validation on the 2022-2024
   development window. EOH is recorded for completeness only.

**Net:** the audit's verdict is that **options features should
not be in the A10 build.** The A6 verdict is "partial keep of
BVOL for the post-2023-06-20 window" and the eventual model
should either (a) live without options for the full
2020-01 → 2024-12 window or (b) include options only as a
post-2023-06-20 feature with a documented regime-mismatch
warning.

## 10. Verdict

**PARTIAL KEEP with severe gap.**

- BVOL index archive 2023-06-20 → 2026-08-29 (1,141 days) is

- EOH summary archive 2023-05-18 → 2023-10-23 (147 days) is

  not-first-party-auditable caveat as A5.
- **Recommendation:** do **not** include options-derived
  features in the A10 build. A future slice can re-evaluate
  Deribit as a separate audit.
